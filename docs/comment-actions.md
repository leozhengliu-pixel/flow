# Suggested actions on comments

In Settings > Agent personalization, **Enable suggested actions on comments** controls suggestions for your new issue comments and replies. It defaults to enabled and is stored with your personal account settings in the current workspace. Turning it off prevents generation for your comments and hides proposals from your view. It does not change other members' settings or execute or dismiss existing proposals.

Flow Agent analyzes human-authored comments asynchronously. An agent mention is not required; mentioning a person alone is not a request to assign them. Application and bot comments do not trigger suggestions. Generation requires configured agent write tools, workspace AI access and editor permission on the issue. Comments are not rescanned on edits. Model failures leave the comment unchanged; there is no automatic retry or historical backfill.

Proposals may change status, assignee, priority or labels, create a sub-issue, or attach an explicit web link from the comment. Arguments are validated against the current workspace. The agent cannot execute a proposal during generation. Any editor with personal suggestions enabled and workspace agent access can accept or dismiss a proposal. Acceptance rechecks its arguments and permissions, then commits the normal mutation, activity and proposal resolution together. Dismissal hides the shared proposal without changing issue properties. A competing resolution returns a conflict; repeating the same resolution never applies it twice.

REST clients use `GET /api/issues/{id}/comment-actions` and `POST /api/issues/{id}/comment-actions/{actionId}` with `{"status":"accepted"}` or `{"status":"dismissed"}`. Each proposal records its comment, issue, target user, action, arguments, status and resolver. Dismissed, missing-comment and stale pending actions are omitted from the list. The bounded web routes under `/api/issue-records` share this behavior. Proposals are omitted from workspace bootstrap responses.

The personal preference is read and patched at `/api/account/settings` using `suggestedActionsOnComments`. This account endpoint requires an interactive account session. The generated TypeScript SDK exposes the typed issue operations and models. MCP clients use `list_comment_actions` and `resolve_comment_action`, with `issueId` and, for resolution, `id` and `status`. Normal read/write credential scopes and issue permissions apply. An application identity cannot generate or accept personal proposals.

Proposal creation and resolution emit realtime events. Accepting a property proposal records the accepting editor as the activity actor and retains `commentId` in activity metadata. Sub-issues and web links use the same helpers as their ordinary creation endpoints.
