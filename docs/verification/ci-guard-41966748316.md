`calc(100vw - 32px)` inside the surface border. The long-chip spec retained its
older right-edge bound and also measured the reopened sheet during its entry

after the actual animation finished, the chip had x=31, width=315 and right=346.
At 390px it settled at x=31, width=330 and right=361. The old bounds still failed
after waiting. Those baseline values use the default whole-pixel browser scale.

requires exact x=30.5 and right=viewport width minus 29.5, replacing a loose
upper bound, and waits for both opening animations.
The existing 16px surface inset, viewport-minus-32 width, 306px height,
ellipsis, full title, filter, selected subscriber and page containment checks
remain. The initial arbitrary 400ms delay is removed. The probe was removed.

The same file's document filter check also failed in CI and the complete local
spec: expected x=22.5, actual x=23. Like the earlier notification-actions fix
`800e6a3f`, this uses the strict gate's browser launch scale and phone context
for reference half-pixel coordinates. The launch option is defined on a derived
test fixture because it is a Playwright worker fixture. Only subscriber and
filter tests use it; the other document tests retain their existing scale.
Subscriber and filter contexts use
the gate's device scale and user agent, and both require the 0.5px surface
border. The filter's exact search and row-label x assertions remain 22.5/58.5.
Its arbitrary 300ms delay is replaced by the actual animation completion.
