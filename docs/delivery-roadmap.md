# Delivery Roadmap

## Delivery Principles

- Build shared behavior before page-specific variants.
- A phase is complete only when its main workflow is functional, not just
  visually present.
- Pixel comparison is performed at representative desktop and mobile sizes.
- Every phase includes loading, empty, populated, error, and permission states.
- Filters and property editors must be shared across product surfaces.

## Phase 0: Foundation

Goal: establish the visual and architectural base.

Scope:

- M01 Application Shell and Navigation
- M02 Design System
- M03 Command and Interaction System
- M04 Workspace and Team Foundation
- M17 Identity, Permissions, and Realtime baseline

Deliverables:

- Authenticated application shell
- Workspace and team navigation
- Light and dark themes
- Shared dialogs, menus, property pickers, and toasts
- Local test fixtures and API conventions
- Screenshot-based visual regression harness

Exit criteria:

- Shell matches the reference layout at target viewports.
- Keyboard focus and navigation work across the shell.
- Workspace and team boundaries exist in the data model.

## Phase 1: Core Issue Product

Goal: deliver a usable issue tracker.

Scope:

- M05 Issue Engine
- M06 Rich Text baseline
- M07 Comments and Activity
- M08 Issue list baseline
- M11 My Issues

Deliverables:

- Create, edit, assign, label, prioritize, and transition an issue
- List and side-detail workflows
- Full issue detail page
- Comments, reactions, subscribers, and activity history
- Assigned, created, and subscribed personal views

Exit criteria:

- A team can run its basic issue workflow end to end.
- Mutations update the list and detail views consistently.
- Core Issue surfaces pass visual regression checks.

Implementation status (2026-08-12):

- Complete: Issue lifecycle, persisted properties, shared pane/full-detail
  state, debounced description autosave, parent/sub-issues, issue relations,
  subscribers, activity, comments, attachments, and bulk changes.
- Complete: Go SQLite persistence and transactional domain events, including
  reopen regression tests and HTTP lifecycle integration coverage.
- Verified in Chrome: create with properties, pane/full-detail shared state,
  autosave, inline sub-issue, comments, blocking relation, bulk priority update,
  and persistence after API restart.
- Remaining Phase 1 polish: richer ProseMirror-class document semantics,
  comment reactions/threading, and automated mobile visual snapshots.

## Phase 2: Information Access

Goal: reproduce Flow's high-frequency navigation and triage experience.

Scope:

- M09 Query and Filter Engine
- M10 Saved Views
- M12 Inbox and Notifications
- M13 Global Search
- M08 Board and advanced list behavior

Deliverables:

- Reusable filter builder and query serialization
- List and board display options
- Saved workspace, team, and personal views
- Search and command-menu navigation
- Functional Inbox with unread, archive, and detail states
- Bulk issue actions

Exit criteria:

- The same filter model powers My Issues, team issues, and saved views.
- Notifications are generated by real product events.
- Search results respect workspace permissions.

## Phase 3: Project Planning

Goal: add planning above individual issues.

Scope:

- M14 Projects
- M15 Initiatives and Roadmap

Deliverables:

- Project list, overview, activity, and issues
- Milestones, resources, progress, and dependencies
- Project updates and health history
- Initiative lists and project aggregation
- Initial roadmap or timeline view

Exit criteria:

- Issue progress rolls up correctly into projects and initiatives.
- Project health and updates have a usable history.
- Workspace and team project scopes remain consistent.

## Phase 4: Collaboration Expansion

Goal: cover team planning and product-feedback workflows.

Scope:

- M16 Cycles and Team Planning
- M18 Pulse
- M19 Customers and Requests
- M06 full Documents experience

Deliverables:

- Cycle planning and rollover
- Team documents and project resources
- Personalized Pulse feed
- Customer directory and request linkage

Exit criteria:

- Teams can plan a cycle and track its completion.
- Customer requests can be traced to delivery work.
- Pulse is derived from actual workspace events.

## Phase 5: Platform Completion

Goal: complete administration, extensibility, and AI-assisted workflows.

Scope:

- M20 AI Agent
- M21 Integrations and Automation
- M22 Settings and Administration

Deliverables:

- Agent chat, history, skills, and controlled issue actions
- Git provider integration and webhook foundation
- Workflow automation rules
- Personal, team, and workspace settings
- Member administration, API keys, applications, and usage pages

Exit criteria:

- Agent actions use the same permission model as direct user actions.
- Integration events are idempotent and auditable.
- Settings cover every configuration introduced by earlier phases.

## Recommended First Milestone

The first milestone should contain:

1. Pixel-matched application shell
2. One workspace and one team
3. Issue list with status grouping
4. Issue creation dialog
5. Issue side panel and full detail page
6. Property editing
7. Comments and activity
8. My Issues assigned view

This is the smallest slice that demonstrates the real product rather than a
static collection of screens.
